# Changed-extent tracking — implementation plan (2026-10-23)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task.

**Goal.** The release is 0.5.0 (owner decision 1). The plan answers FR-26 ("Changed-extent tracking
to remove the scan floor"), the open decision D1 and PRD §8's SM-1b (a 5 min median warm downtime independent of disk
size), which no release delivered:
- An OpenStack or RHOSO source provider holds a Ceph access - the cluster's fsid, its monitors, a Ceph user - and the
  user's key, write-only, stored as `provider-{id}.ceph`. A plan turns tracking on (`extent_tracking`, off by default).
- Each warm pass of a qualifying disk - a Cinder RBD volume of that cluster, not encrypted - runs
  `rbd diff --whole-object` on the source conversion host for the extents written between Cinder's own pass snapshots;
  the last completed pass's snapshot stays as the next pass's base. Nothing writes to Ceph, and the temporary volume
  stays the read path.
- Pre-copy, sync and keep-warm passes scan in full and check the extents against what changed; the final pass reads
  only the chunks the extents name (blocksync protocol v2). Any doubt, and any miss, scans the disk in full, as today;
  tracking never fails a pass.
- The estimator drops the scan from a tracked final pass (`extent_query_s`); three findings, the dashboard and the demo
  show it. libvirt dirty bitmaps stay out (SDD §28.7). Tracking is a Technology Preview until LAB-CE01–LAB-CE07 and
  PERF-E2E-SM1b pass.

**Spec:** SDD §28 and D1. Each item becomes binding when its task moves it into the section §28.12 names. The PRD changes with CE1.

**Decisions:** the owner took the ten defaults of SDD §28.11 as written on 2026-10-23 (D1).
The research behind the design was done on 2026-10-23: the rbd(8) page and librbd's diff code (`Diff.cc`,
`DiffIterate.cc`, `object_map/DiffRequest.cc`, `rbd.pyx`), Ceph's RBD configuration and user-management pages, Ceph
trackers #53784 and #61616 with their backports, Cinder's RBD driver, name templates and Ceph backup driver, Nova's
image backend and guest code, libvirt's checkpoint and backup XML pages, virsh(1), its incremental-backup internals and
NEWS, oVirt's incremental backup feature page and MTV 2.4's documentation. The pull request that proposes this plan
lists the sources.

## Rules for every task

- **The SDD comes first.** The amendment that makes a task's item binding is its own commit, by the controller
  (CLAUDE.md §1, §3), and it moves the item from §28 into the section §28.12 names. The SDD-reading tests stay green:
  - the route enters §12's table with its task and `test_role_matrix`'s `ROUTES` in the same pull request, since
    `test_every_route_is_documented_in_sdd_12` and `test_the_role_matrix_covers_every_route_sdd_12_lists` read both;
  - a finding enters §9.3 with `planning/preflight.CATALOG`, the shared fixtures (`eligibility_cases.json` and
    `finding_catalog.json`, rewritten in their exact formats), the dashboard's `findingCatalog.ts` and mock, and
    QASuite FR-04's counts (`test_the_qasuite_counts_the_mocks_codes_and_the_shared_finding_cases`); its tests are
    named `test_finding_<code>` (`test_each_finding_code_has_a_test_named_for_it`);
  - no event kind is added: `migration.sync_pass` carries the new `extents`, `provider.credentials_updated` the Ceph
    secret's name; no variable is added to §15.1 and no metric to §18.
- **TDD.** The named tests fail first, for the stated reason, then pass. Mutants of the new logic are killed. A test
  named here keeps its name. The `bad_version` case of `tests/unit/test_blocksync.py`'s protocol-error test, which
  expects "unsupported protocol version 2", moves to version 3 with CE2.
- **Tracks.** Track ownership is as in CLAUDE.md §3: A the collection (blocksync, the extent query, the warm modules
  and roles, `conversion_host_content`), B the control plane, C the dashboard, D the documents. Where a contract binds
  two tracks (the pass record, the findings, the estimator's port), the task's pull request carries one commit per
  track.
- **QASuite.** Each task's pull request adds its QASuite rows (track D), naming the tests it landed.
- **Paths.** `tests/unit/` is the collection's (the repository root); `tests/test_*.py` and `tests/lab/` are the
  control plane's (`seamless/tests/`), as in the other plans.
- **The conversion hosts' Python.** `blocksync.py` and every module_utils file that runs on a conversion host stay
  Python 3.6 standard library (§6.2, D7): QASuite §14.2's container run on 3.6 and 3.8 passes before each A task merges.
- **Never a read without its conditions.** A test that expects a `read` pass without a clean check of the disk, from a
  base that did not read the destination in full, after a destination server held the volume, or from a base Cinder
  no longer has, means the design is wrong (SDD §28.5).
- **Never a failure from tracking.** A test that expects a pass, a cutover or a migration to fail because the extent
  query failed, timed out or was refused means the design is wrong: the disk scans in full, with its reason.
- **Synthetic fixtures:** no real Ceph in CI. The collection's tests run a fake `rbd` executable that answers JSON
  extents from a model of the writes, on file-backed devices; fsids, monitor addresses and keys are made up in the
  test. A Ceph key never reaches a log line, an event, an error, a check report, `vars.yml` or a test's failure
  message.
